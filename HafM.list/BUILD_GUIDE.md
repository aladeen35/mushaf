## 3. البنية
- كل صفحة ملف HTML صغير (`<main id="page">`) + `config.js` + `data.js` + `core.js` + سكربت الصفحة في `assets/js/pages/`.
- `core.js` يرسم الشريط العلوي (الشعار/رجوع، العنوان، مبدّل ع/En، صورة الحساب) والشريط السفلي (5 تبويبات) عبر `renderShell()`.
- كل صفحة محمية بـ `requireAuth()` — بدون جلسة يُحوَّل المستخدم إلى `index.html?next=…` ثم يعود بعد الدخول.
- التنقل بين الصفحات روابط عادية، والحالة داخل الصفحة في الرابط (`list.html?id=1&city=Riyadh`) فيعمل زر الرجوع.

## 4. نموذج البيانات (`localStorage` → `hafmList.v2`)
```js
{ version: 2, lang: 'ar',
  users: { 'name@halfm.sa': { email, name, pinHash, createdAt, lastLogin, fails, lockUntil } },
  perms: { 'other@halfm.sa': 'editor' | 'admin' },          // صلاحيات ممنوحة على هذا الجهاز
  checklists: [ { id, name, nameAr, kind: 'fixed'|'survey', slug, icon, tone, locked, archived,
                  items: [ { id: 'hibiscus', label: 'Hibiscus', labelAr: 'كركديه' } ] } ],
  reports: [ { id, checklistId, weekStart: '2026-11-21', weekEnd: '2026-11-27', date,
               checks: { '18': { s: { hibiscus: 'Okay', … }, remarks, auditor, email, at, history } } } ],
  quiz: { correct, total, streak, best }, nextId, lastEmail }
```
- **الحالات مخزّنة بمعرّف البند** (`s[itemId]`) لا بالترتيب — تعديل/حذف/ترتيب البنود لا يخرب البيانات القديمة.
- `"Not checked "` تُحفظ **بالمسافة الأخيرة** كما في الإكسل (مهم لمعادلات `COUNTIF`)، وتُمرَّر في HTML بالفهرس `data-sidx`.
- الجلسة في `sessionStorage` (`hafmList.session`) — تنتهي بإغلاق المتصفح، فيُطلب الرمز في الزيارة التالية.
- التقرير البذرة (من الإكسل الأصلي): أسبوع 2026-10-31، تاريخ 2026-11-01، 50/106 فرعاً — 425 Okay، 9 أُصلحت، 3 غير مصلحة، 9 لم تُفحص، 4 غير متوفرة، وملاحظتا B08 وB44 حرفياً.
- ترحيل تلقائي من النسخة الأولى (`halfMillionQualityAppV1`) عند أول فتح.

## 5. الدخول (index.html + pages/login.js)
1. **الافتتاحية**: شعار ½M مرسوم بأربعة مسارات SVG تظهر متتابعة + دوائر Teal/Havan (1.9 ثانية أول مرة في الجلسة، 0.7 بعدها).
2. **الترحيب**: بطل داكن + 3 مزايا + زر «ابدأ — تسجيل الدخول».
3. **الإيميل**: يُقبل فقط إن انتهى بنطاق من `ALLOWED_EMAIL_DOMAINS`.
4. **حساب جديد**: الاسم الكامل ← اختيار رمز (يُرفض 1111، 1234…) ← تأكيده.
5. **زيارة لاحقة**: يتذكر الجهاز آخر إيميل (`lastEmail`) ويعرض لوحة الأرقام مباشرة مع «ليس حسابك؟».
6. `pinHash = sha256('hafm-pin|' + email + '|' + pin)` — SHA-256 مكتوب في `core.js` ليعمل حتى على http و file://.
7. «نسيت؟» ← يعيد المشرف تعيين الرمز من «حسابي»، فيختار المستخدم رمزاً جديداً عند دخوله.

**الصلاحيات** — `roleOf(email)`:
`admin` إن كانت `sha256('hafm-admin|' + email)` ضمن `CONFIG.ADMIN_EMAIL_HASHES`، وإلا `state.perms[email]`، وإلا `auditor`.
إن كانت قائمة المشرفين فارغة فأول حساب على الجهاز يصبح مشرفاً.

## 6. التدفق
`home.html` (بطاقة لكل قائمة) → `list.html?id` (المنطقة → الفرع) → `entry.html?list&branch` (التعبئة) → حفظ يعود لصفحة المنطقة، أو «حفظ والفرع التالي» ينتقل لأول فرع لم يُدخل في نفس المنطقة.

صفحة التعبئة: بطاقة فرع داكنة (الكود، الرقم، المدينة، المنطقة الإدارية، المدير، القائمة، التاريخ)، شريط امتلاء X/Y،
«الكل سليم»، «نسخ من آخر تقرير»، «مسح»، بطاقة لكل بند (2 حالة في الصف للثابت، 3 أزرار كبيرة للسيرفي)، تنبيه أحمر فوري عند Not fixed / ❌،
ملاحظات، أزرار حفظ ثابتة أسفل الشاشة، تنقل للفرع السابق/التالي، وتحذير عند مغادرة الصفحة بتعديلات غير محفوظة.

## 7. الأسابيع والتاريخ
السبت → الجمعة بتوقيت `Asia/Riyadh` (`Intl.DateTimeFormat`). `ensureCurrentWeek(listId)` ينشئ تقرير الأسبوع تلقائياً، وتاريخه = السبت (مطابق لقالب 2026-11-14).
التواريخ داخل الجمل العربية تُعزل بـ `D()` (LRI…PDI + شرطة غير قابلة للكسر) حتى لا تنقلب أرقامها.

## 8. Excel (export.js)
**المشروبات** — مطابق للقالب الأصلي خلية بخلية (تم التحقق آلياً: 0 فروقات في خلايا القالب):
الصف 1 عنوان مدموج A1:S1 بتعبئة `#1F4E78` وخط أبيض 16 عريض وارتفاع 32.1؛ A2 `Date:` وC2 التاريخ بتعبئة `#FFF9E5`، وM2:S2 مدموجة بنص الخيارات رمادي مائل؛
الصف 4 ترويسة (A–M وS كحلي، N–R `#2F75B5`)؛ الصفوف 5–110 الفروع (`=ROW()-4`، E–M كريمي، N–R `=COUNTIF($E5:$M5,N$4)`)؛
قائمة منسدلة واحدة على E5:M110؛ تنسيق شرطي للحالات الأربع + اسم الفرع بالأحمر إن `$P5>0`؛ الصف 112 `SUMMARY BY PRODUCT` والصفوف 113–117 `=COUNTIF(E$5:E$110,$A113)`؛
عروض الأعمدة كالأصل، D مخفي، تجميد عند E5، طباعة أفقية Fit to width وصف الترويسة مكرر.
**باقي القوائم** — نفس الأسلوب بأعمدة ديناميكية: No., Code, Branch, Area Manager (مخفي), City, البنود, عدّ لكل حالة, Auditor, Remarks + ملخص حسب البند.

## 9. القوائم (admin.html)
إنشاء/تعديل: الاسم بالعربية والإنجليزية، النوع (سيرفي ✅/❌/N/A أو ثابت بخمس حالات — لا يتغير بعد وجود إدخالات)، أيقونة من 12، لون (Teal/Havan/داكن)،
بنود قابلة للترتيب والحذف، ولصق دفعة واحدة (`English | العربية`). الأرشفة تخفي القائمة وتبقي تقاريرها؛ الحذف فقط لقائمة بلا إدخالات.
المشروبات و Hot Cookies **مقفلتان** لأنهما مرتبطتان بالقالب الأصلي ورسالة الواتساب.

## 10. PWA
`manifest.webmanifest` (اسم، ألوان، أيقونات 192/512/maskable) + `sw.js` (تخزين ملفات التطبيق مسبقاً، الصفحات Network-first، الملفات Cache-first).
بعد أول زيارة يعمل التطبيق دون إنترنت (ويظهر شريط «أنت غير متصل»)، ما عدا أول تحميل لمكتبة Excel.
عند تعديل الملفات: غيّر `CACHE` في `sw.js` (مثلاً `hafm-list-v2`) ليحصل المستخدمون على النسخة الجديدة.

## 12. القيود ونقاط التوسع
- **لا مزامنة سحابية**: كل جهاز يحفظ بياناته؛ النقل عبر نسخة JSON. الخطوة التالية المقترحة: Backend (Supabase/Firebase) لجدولي `reports` و`checklists`
  واستبدال `loadState/save` بمزامنة — والدخول الحالي (إيميل + رمز) يتحول إلى Auth حقيقي (Magic link أو OTP على إيميل العمل).
- **الصلاحيات محلية**: الصلاحيات الممنوحة من صفحة الحساب تخص الجهاز؛ المشرفون الدائمون في `config.js`.
- **لا صور/مرفقات** في الإدخال.
- **المدن مستنتجة من أسماء الفروع** (انظر `data.js`) — راجعها قبل الاعتماد.
- **12 مخالفة بعناوين فقط** — لا يُخترع لها شرح، ولا تدخل في بنك أسئلة الاختبار.
